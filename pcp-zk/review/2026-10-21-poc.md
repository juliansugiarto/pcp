# Soundness PoC: the current Table16 gadget accepts a forged H

Date: 2026-10-21. Machine: 2 CPUs, ~7 GB RAM. halo2_proofs 0.3.5, IPA/Pasta.
Tool: halo2 `MockProver` at `k = 17` (constraint satisfaction, not a real proof).

## What was tested

Two test-only witness overrides were added to the vendored Table16 gadget,
compiled only under `cargo test` of the library crate (`#[cfg(test)]`):

- `A_FINAL_DELTA` (review C-4): added mod 2^32 to the witness of `a_final` in
  round 63 (`src/sha256/table16/compression/subregion_main.rs`).
- `K63_DELTA` (review C-1): added mod 2^32 to the advice value used for the
  round constant `K_63` (`src/sha256/table16/compression/subregion_main.rs`,
  feeding `assign_h_prime`).

The PoC tests live in `src/poc.rs` (declared `#[cfg(test)] mod poc;` in
`src/lib.rs`). A reference single-block SHA-256 with a caller-supplied `K`
table lets the tests compute exactly what the circuit outputs under each
tamper.

## Result: CONFIRMED (both exploits reproduce)

```
test poc::poc_c1_k63_is_free ... ok
test poc::poc_c4_a_final_is_free ... ok
test result: ok. 2 passed; finished in 96.74s
```

Each test asserts three things, all of which held:

1. The honest in-circuit SHA-256 equals `sha2::Sha256` (the reference with the
   standard `K` matches `suite::payment_hash`).
2. With the hook OFF, the forged `H` is REJECTED by `MockProver` (`verify()`
   returns an error). So the forgery is not accepted by accident.
3. With the hook ON, the forged `H` is ACCEPTED (`verify()` is `Ok`), while
   that `H` is provably not `SHA256(k)` (`assert_ne!(forged, SHA256(k))`).

### C-4 (a_final free)

`a_final` in round 63 is a fresh cell with no copy constraint from the
`s_a_new` output. Adding 1 to its witness shifts digest word 0 by 1. The
feed-forward gate in `circuit.rs` reads the (now tampered) dense value, so it
stays internally consistent, and output word 0 becomes `word0 + 1`. Setting
the instance `H` word 0 to `word0 + 1` makes the circuit accept. This is the
simplest exploit: no reference recomputation is needed, the forged `H` is just
the honest `H` with its first 32-bit word incremented.

### C-1 (K_63 free)

`K_63` is assigned to an advice column with nothing tying it to a constant.
Replacing it with `K_63 + 1` changes `H'` in round 63, hence both `A_new`
(digest word 0) and `E_new` (digest word 4). The circuit then computes a
SHA-256 with a tampered `K[63]`. Setting the instance `H` to that tampered
digest makes the circuit accept, and that digest is not `SHA256(k)`.

## Impact

A malicious seller can issue a BOLT11 invoice with `payment_hash = H` for an
`H` that is not `SHA256(k)`, prove the sale statement so the buyer's `verify`
returns OK, take payment, and the buyer receives a preimage that does not
decrypt the solution. This breaks the ZKCP guarantee. The verifying key and
constraint system are unchanged; only the prover's (attacker-controlled)
witness generator differs.

## Disposition

The Table16 gadget is replaced by an auditable in-house SHA-256 chip (see
README and the adversarial test suite in `src/adversarial.rs`). The
hooks and this PoC module are removed once the replacement lands; they are kept
here only as the record that the finding was reproduced on the original code.
